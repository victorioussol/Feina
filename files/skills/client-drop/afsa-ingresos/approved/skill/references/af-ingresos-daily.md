# Original-workbook daily reconciliation implementation

Apply the output/approval contract in SKILL.md in full. This reference adds execution detail, not a second copy of the standing format rules.

## Resolve deployment and source identity
1. Read the current runbook and configuration under `/root/.hermes/automation/af-ingresos/`. Resolve the original workbook ID, current filename, current approved email template, source merchant/terminal filters and completed-date state there; do not hardcode historic run results or sent-message IDs into new work.
2. Run `hermes cron list`, `hermes cron doctor`, then `hermes cron history <job-id>` using the ID returned by the list. Inspect the exact due execution, its retained `last_failure`, and the local run log/audit for that business date; compare them with `last-success.json`, because a later gate skip or a scheduled tick does not prove the workbook was updated. Identify the earliest failed stage before proposing a rerun. For an approved Composio Drive/Gmail route, check whether an attached local-OAuth google-workspace skill is actually used before requiring its separate credential setup. With approval, remove an irrelevant dependency from the existing job rather than disabling global preflight, creating dummy credentials, initiating unnecessary OAuth or creating a duplicate job. Read the changed job back and rerun the readiness check; keep the approved schedule, safety conditions, delivery scope and file identity unchanged. Diagnose and verify the business-date update and email separately as required by SKILL.md.
3. On a UTC scheduler without per-job timezone support, `0 2,3 * * *` plus `time_gate.py` gates execution to local04:00 using ZoneInfo Europe/Madrid and skips completed business dates. `/root/.hermes/scripts/af_ingresos_gate.py` is the wrapper. Do not change the global timezone.

## Collect and normalize
4. Download fresh original metadata/content and retain a private backup. Read formulas and cached values separately before editing.
5. Retrieve complete previous-local-day POS rows with the correct gym, inclusive boundaries and verified row count. Separate automated DDMS from in-club POS. Sum signed line subtotals, not a received amount repeated across products; retain original positive sales and negative refunds on their actual dates. For React Select controls, invoke the mounted component's `selectOption` with an option read from its own `options`, or use the UI; the input child's `onChange` expects a DOM event, not an option object. Use the datepicker's existing selected/onChange/dateFormat component to commit local Date boundaries, then verify displayed/applied filters. Extract only allowlisted financial fields from the report container, never wholesale props or identity-document data.
6. Search the connected Gmail account over a sufficiently broad delivery window, paginate, hydrate and download matching processor PDFs. Use operation dates inside the PDFs. Preserve provider completeness, extracted counts and declared-total checks in private evidence. Successful absence and failed access are different outcomes.
7. Build a daily payload with business_date, gym, membr_available, mailbox_search_succeeded, pos_total_net, pos_card, pos_noncard_net, payment_report_found and payment_reports_total. Use decimal strings and require total = card + all noncard net. Preserve unknown-provider flags outside the visible workbook.

## Stage and commit
8. Use the current `update_workbook.py` against the newly downloaded original. Example through `terminal`: `python update_workbook.py downloaded.xlsx daily.json staged.xlsx`. Test positive and negative differences, known matched zero, missing-source zero and verified all-zero activity. Compare non-target values/formulas/caches, tabs and conditional-rule priority. Do not use obsolete helpers implementing coloured cell backgrounds.
9. For formatting-only corrections, leave all financial XML and cached results unchanged; see xlsx's style-only editing reference. Read serialized cell style IDs from worksheet XML rather than normalized openpyxl Cell.style_id when indexing styles.xml.
10. Stage the actual workbook bytes via Composio workbench `upload_local_file` and pass its real s3key to GOOGLEDRIVE_UPLOAD_UPDATE_FILE with the original fileId and binary media upload. Never create a replacement file or convert it to Sheets. Immediately before the write, compare fresh original checksum/modification time with the downloaded version; abort/rebase on concurrent edits.
11. Read original metadata back, download the exact target, compare checksum/values/caches/tabs/history and verify both white fill channels plus number colours in base and conditional styles. Render a temporary preview copy when display changed; never save print-preview alterations back to the original. Update last-success.json only after verified persistence.

## Diagnose a missed update or alert
Before reporting why the report or alert is missing, compare the job's exact scheduled execution, per-date run log/audit, `last-success.json`, and per-date alert state. State the latest business date whose workbook read-back is verified, then identify whether the failure occurred during source retrieval, validation, staging, Drive write/read-back, or email delivery. A schedule firing is not a workbook update, and an absent alert is not evidence of a zero variance: if an upstream source or validation failed, say the comparison was not established and the alert branch was not reached. Distinguish a deferred catch-up alert from a failed send. Do not perform historical reruns or resend an alert unless the applicable authorization permits it.

## Conditional alert
12. Stage the just-read-back-verified original for attachment. Save attachment JSON with exactly name, Excel mimetype and actual staged s3key. Through `terminal`, render `python render_alert.py daily-payload.json --verified --attachment-json attachment.json`. Never pass verified merely because an upload call returned success.
13. If an alert is required, inspect private per-day alert state and Gmail Sent for recipient, exact subject and figures. If already sent, retain the message ID and do not resend. If absent, use the renderer's exact approved send_arguments. Do not repurpose a one-off test as authority for further test/backfill sends.
14. Read back the exact sent message and attachment; verify To, empty additional recipients, subject/body, SENT state, filename and attachment hash against the verified original. Record confirmed or uncertain outcome; check Sent after timeouts before retrying.
15. Keep scheduled run/failure output local unless separately authorized. Link the aggregate run note, private evidence and workflow note without publishing member details or secrets.
