# Membr card reconciliation

## Client output contract and approval scope

Apply these rules before extracting or editing data:
- Preserve the supplied income-control layout and original Drive workbook rather than introducing a redesigned dashboard. Keep compact 16-point daily rows, familiar column order, the .xlsx filename extension, and existing annual tabs. Add a tab only for a new year; keep audit/detail data outside the original workbook. Locate columns by their headers rather than assuming every annual tab has identical positions.
- Keep Dif banco/tarjeta data-cell backgrounds WHITE. Colour only the NUMBER: green FF008000 for a known zero difference, red FFFF0000 for a known positive/negative difference, black FF000000 for missing-data placeholders. Use numeric 0 for missing values, not blank cells, while preserving unknown-source status separately. A black placeholder zero is not a matched day. Set explicit FFFFFFFF in both solid-fill channels and correct font colours in base AND conditional styles; avoid number-format colour directives. Compare rounded cents and give verified per-day rules priority over general missing-data guards.
- Do not add visible comments or annotations by default. Preserve existing cell notes/comments and text in the comments column when editing. If asked to restore comments, inspect the current header row and hidden-column state; distinguish text in the dedicated comments field from Excel notes/comments attached to cells, and inspect available revisions/backups for an exact source before editing. Never infer or recreate missing text, equate a column letter with a field name, or change visibility when the requested target is ambiguous. Restore only content found in a trustworthy source, preserve all other workbook data, and verify the latest revision before and after writing; if no source is available, ask for the prior copy instead of guessing. The current AFSA Ingresos 2026 layout labels column H “Comentario,” but confirm headers on each annual tab because positions can differ.
- Sum all net non-card methods, including transfers, in the original other-methods column so total minus non-card equals card income. Calculate difference as available payment reports minus Membr card income.
- Distinguish a successful search with no report from a failed connection. Display the approved black zero only for missing-source data; stop without overwriting valid figures on access/retrieval failure. Membr is strictly read-only; stop on login/captcha/verification rather than retrying authentication.
- The approved AF Sant Adria recurring workflow updates the previous local calendar day at 04:00 Europe/Madrid with DST handling. Preserve original Drive ID, folder, sharing, values outside the target date, formulas and cached results. If the current original cannot be fetched/read or its revision is stale, do not overwrite it from an older local artifact; request the current revision or prepare a clearly separate, uncommitted draft. Read the written original back before declaring success.
- Mandatory checks are run exactly as installed: `afsa_checks.py` (dates, export, final, gaps), the gate and the assertions in `update_workbook.py`. Never patch, monkeypatch, re-implement or override them in memory, in a copy or by editing inputs so they pass. A FAIL means stop: no Drive write, no state or ledger update; report the FAIL. Code changes need Victor's approval.
- Membr export sent by Vince (e.g. on Telegram): use it only as the POS source of the normal stage → verify → commit pipeline, never as a reason for a direct Drive write. Save it as `runs/<D>/pos-export.xlsx`, then in order: (1) `afsa_checks.py export --business-date <D> --slack-on-fail runs/<D>/pos-export.xlsx` and copy its pos_total_net, pos_card and pos_noncard_net unchanged into daily-payload.json; (2) `afsa_checks.py dates --business-date <D> --slack-on-fail <payment PDFs>`; (3) download the current original, stage it with `update_workbook.py`, verify only the target row changed; (4) upload in place, read back, write last-success.json, then `afsa_checks.py final --business-date <D> --since <run start> --slack-on-fail` and `afsa_checks.py gaps --business-date <D+1> --slack-on-fail`. On any FAIL, stop and only tell Vince briefly, in his language and without technical detail, that it is being checked (ops see the FAIL in Slack).
- Validate recurring readiness against the actual approved connection route and every attached skill's declared prerequisites. Treat a due scheduled execution, a verified original-workbook update and a verified conditional email as separate outcomes; isolated manual tests do not prove the complete scheduled workflow. Inspect the due tick itself because a later expected timezone-gate skip may overwrite the summary status with ok. An absent email is not evidence of a zero difference. Diagnose without writes first and obtain approval before permanent deployment changes or missed-date reruns outside the approved schedule.
- Recurring email authority is narrowly scoped: exact approved short Spanish subject/body with verified placeholders, only to CLIENT_EMAIL_REDACTED, no Cc/Bcc or additional content, and the exact verified original workbook attached. Send only after a verified update with a known nonzero difference, at most once per business date. Check Sent before retrying and verify the resulting message and attachment. Missing-data zeros, zero differences, source failures and unverified writes generate no alert. Other messages, tests or broader scope require fresh draft/approval.
- Compare processor reports separately from actual bank settlement; do not describe a green zero as proof of money credited to the bank or this POS control as full gym revenue/profit.

For the daily implementation sequence and concrete helpers, load `references/af-ingresos-daily.md`; resolve current deployment identifiers and the approved template from its runbook/config rather than copying old run state into the skill.
